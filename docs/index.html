白話描述一筆申請 → 過官方驗證的健保 FHIR + 「會不會被核刪」的預測。

要送健保事前審查(TWPAS),你得產出符合官方 IG 的 FHIR。

自己串 FHIR:啃完整本健保 IG、填對 40+ 個 profile 與每個固定值、 跟 TW Core 術語坑纏鬥、自己除到官方 validator 0 錯 —— 做完還是沒有送前核刪自查。

用這個 framework:給一筆白話案子(不碰 FHIR), 直接拿到 0-errors 的 Bundle + 會不會被核刪的預測。IG 的髒活我們替你做完、而且對得上官方。

看一個實際例子

你給它(白話,不碰 FHIR)
  • 病人、醫師、醫院
  • 診斷 ICD：C90.00(骨髓瘤)
  • 想申請：乳癌藥 Abemaciclib(BC27730100)
→
它給你
  • ✅ 一份 FHIR Bundle,28 resources,過官方 HL7 validator 0 errors
  • 🔴 CQL 自查:會被核刪
    理由(規則自己給的):主要疾病之 ICD 代碼未使用 C50(骨髓瘤≠乳癌)

「這對不對?」全部可自己驗:產出的 Bundle 對照官方範例 Bundle-bun-1、能拿官方 validator 驗到 0 錯; CQL 用的是官方公開規則。
官方來源 → 健保事前審查 IG · 官方 CQL 規則 IG

你只需要懂這兩個名詞

FHIR
醫療資料交換的國際標準格式(健保規定用它交換申請)。你不用懂它 —— 我們把你的資料翻成它。
CQL
健保把「哪種藥、什麼條件才給付」寫成的公開審查規則。我們拿同一套,在你送出前先跑一遍。

怎麼接進你既有的系統

你系統已有這筆資料 → 填成中性的 PACase(不碰 FHIR)→ 呼叫一行。上面例子的程式就是:

var c = new PACase(CaseType:"cancer-drug", /* 病人/醫院/vitals */
    Data: new(){ ["drug_code"]="BC27730100", ["diagnosis_icd"]="C90.00" });

var r = await Pipeline.RunAsync(c, cql: check);   // 產 FHIR + 送前 CQL 自查
if (r.Blocked) show(r.Cql);   // 會被核刪/補件 → 先修
else submit(r.Bundle);        // r.Bundle 可直接送
① 產組 FHIR→② 驗→③ 查CQL→④ 送→⑤ 回

長照怎麼用? 長照是同一套 TW Core 地基上的另一本 IG,接法跟上面一樣、只換 CaseType —— 但誠實說:長照組裝器在路線圖上,尚未實作。目前實作的是健保事前審查。
